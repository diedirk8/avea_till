# Coding Standards

## Philosophy

Code should be simple enough that another developer can understand it without explanation.

Readable code is preferred over clever code.

---

# General Principles

- Keep methods short.
- One responsibility per method.
- Prefer descriptive names.
- Remove unused code.
- Avoid duplication.

---

# Python

- Follow PEP 8 where practical.
- Prefer Odoo ORM over raw SQL.
- Keep business logic inside models.
- Use comments to explain "why", not "what".

---

# XML

- Keep views clean.
- Group related fields together.
- Use meaningful IDs.
- Avoid unnecessary inheritance.

---

# Git

- One logical feature per commit.
- Write meaningful commit messages.
- Never commit broken code.

---

# Development Workflow

1. Build
2. Test
3. Commit
4. Push
5. Deploy

---

# Documentation

Whenever an important architectural decision is made, update the documentation before continuing development.

Good documentation is part of the software.
